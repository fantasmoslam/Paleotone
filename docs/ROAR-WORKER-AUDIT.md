# ROAR worker eligibility audit

Experimental branch based on81bae2a; no device install authorized by validation yet. The working device remains unchanged.

ROAR's mutable synthesis state is voice-local: phases, local noise seed, filter memories, drum progress, stage and RING ramp. It does not draw from shared formant_nz or the global RNG. Recipe/tuning tables and hash helpers are read-only. Tuning uses the owning track's parameters. Shared reads are song.playing, beat_samples (internal BPM or measured MIDI clock), crank.speed and crank.strokes.

Ownership contract: CPU0 audio interrupt runs events_block/scm_block/perf_begin before launching work; CPU0 joins before effects/next events and before returning to foreground UI. MIDI clock writes happen in audio events; UI crank writes happen only in ui_input on CPU0 foreground, which cannot execute during that interrupt. TIMER5 scans/enqueues but does not run these control writers. Other concurrently rendered tracks do not write these globals. Thus the shared values are stable for the joined rendering interval; no extra snapshot or RAM state is required under the current scheduling contract. If UI/events become independently threaded or write during a pending job, this conclusion must be revisited and inputs snapshotted.

Audit experiment removes only ROAR's conservative exclusion. VOICE/SAURUS stay excluded and any PHYS track still disables splitting. Existing worker mailbox, fallback, shared voice budget and sound equations stay unchanged. Existing tests' worker-participation predicate is updated so ROAR scenes must actually execute on the worker. New scenes cover mixed ROAR/SAURUS/FM6/VOICE and four ROAR tracks with between-block changes to all19 pulse modes, crank speed/strokes, internal/external clock values, tempo, transport and RING. These changes deliberately occur outside jobs, matching firmware ownership; asynchronous control writes would violate that ownership rather than constitute a valid test workload.

Required validation before hardware: actual worker execution with every split, bit-exact output, existing goldens and ROAR corner tests, ThreadSanitizer, target stack/memory/budget guards and matching companion. Then fresh baseline/state backup, identity-pinned installation, actual-worker counters/stack/wait/faults, USB/deadline measurements and exact saved-state verification/restoration. No performance gain or production safety claim yet.
